## 1. Deploy & Infrastructure — the two that bite in prod

### P1 — SSE stream has no proxy-buffering kill → live assistant hangs behind Dokploy/Traefik
`app/api/agent-stream/route.ts:81-85` (`SSE_HEADERS`)

`SSE_HEADERS` sets `Content-Type: text/event-stream` + `Cache-Control: no-cache, no-transform`
but **omits `X-Accel-Buffering: no`**. Behind an nginx-class reverse proxy (Traefik on Dokploy,
or any CDN layer), the response is buffered and the per-delta streaming collapses into a single
end-of-turn flush — the headline live-assistant chat appears to hang until the whole reply is
ready. Passes every local test because there's no proxy locally.

**Fix:** add `"X-Accel-Buffering": "no"` to `SSE_HEADERS`; confirm no buffering layer sits in front
on Dokploy. One line, highest user-facing impact in the whole audit.

### P1 — `docker-compose.yml` defaults the Convex backend to `:latest`
`docker-compose.yml:44` — `image: ${CONVEX_SELF_HOSTED_IMAGE:-ghcr.io/get-convex/convex-backend:latest}`

The file's own header (lines 6–8) says **"NEVER use `:latest` for convex-backend in production —
pin a digest"**, yet the fallback when the env var is unset *is* `:latest`. A stray
`docker compose pull` can silently jump backend versions against the stateful `convex_data`
SQLite volume (the comment itself calls it "the only durable asset"). Backend/schema-format skew
is the data-loss class of failure.

**Fix:** make the default a pinned digest, or fail loudly when `CONVEX_SELF_HOSTED_IMAGE` is unset
instead of falling back to `latest`.

### P3 — Observability is a documented no-op, but the site is no longer "just docs"
`instrumentation.ts:6-9,14` — `register()` empty, `onRequestError` console-only.

Defensible when it was a read-only docs site; less so now that it runs a live AI assistant (real
upstream spend + failure modes) and a Convex-backed rate limiter. **Fix:** wire `onRequestError`
to a real sink (structured log shipper) now that paid/stateful paths exist.

### P3 — `fs.readFileSync` at module-load for version badges
`lib/content/package-versions.ts:11-21`

Reads `packages/{cli,mcp}/package.json` synchronously at import time with a silent `"?"` fallback.
The paths *are* in `outputFileTracingIncludes` (`next.config.mjs:27-28`) so the standalone image
works today — but this is exactly the failure-mode class CLAUDE.md's "Forbidden" fs-read rule warns
about: if `.dockerignore` ever drops `packages/`, badges silently render `?` in prod with no error.
**Fix:** none required; keep tracing ↔ `.dockerignore` in sync, ideally move into a `use cache` boundary.

## 2. Security — copy-source / consumer-template hardening

> These functions live in `convex/features/*` which is **copy-source** — they do **not** run on rr's
> own backend (the deploy allowlist keeps them off it, which is the correct design). The risk is to
> downstream consumers who copy them via `npx rr add`. Still worth fixing in the template before more
> consumers inherit the footgun.

### P2 — `ai/callModel` is the one paid-AI action with no key-guard and no rate-limit
`convex/features/ai/action.ts:22` — `createOpenRouter({ apiKey: process.env.OPENROUTER_API_KEY! })`

Non-null assertion means a missing key throws at runtime instead of degrading. Its sibling
`aiChat/chat` (`convex/features/aiChat/action.ts:37-42`) is key-guarded and returns
`{ ok:false, notice }` gracefully. As a public `action()` with no auth gate and no rate limiter,
once a consumer sets `OPENROUTER_API_KEY` any anonymous caller drives unbounded paid spend.
**Fix:** mirror the `aiChat` key-guard + add a `rate_limit.consume` gate (`ai:<ip>` prefix).

### P2 — Paid LLM actions have no rate-limit before the model call
`convex/features/aiChat/action.ts:21` (and the `ai` slice generally)

`aiChat` degrades gracefully but still allows anonymous unbounded Anthropic spend once configured.
**Fix:** add a `rate_limit.consume` gate before the LLM call in the consumer template.

### P2 — `payment getPaymentStatus` is an open, cross-tenant status proxy
`convex/features/payment/actions/doku.ts:179`

Public `action()`, no auth / no owner check / no rate-limit. Takes any `orderId` and proxies DOKU's
status endpoint, returning status/paidAt/txId/channel for **any** order including other tenants'.
The reactive `getOrderByOrderId` query guards ownership; this action bypasses it.
**Fix:** require owner check or capability token + rate-limit; at minimum document the exposure.

### P2 — `activity.listAll` returns non-public rows
`convex/features/activity/query.ts:13` (vs `listPublic:23`)

`listPublic` filters `visibility:"public"` via `by_visibility_occurredAt`; `listAll` uses
`by_occurredAt` with no filter and no `requireAdmin`, yet is exposed as a public `query`. If a
consumer stores private/internal activity, anonymous callers read it.
**Fix:** gate with `requireAdmin` or rename/document as admin-only.

### P3 — KaTeX parse-error message interpolated into `dangerouslySetInnerHTML` unescaped
`frontend/slices/notion-shell/components/blocks/EquationBlock.tsx:31,77,94`

The catch path builds an error `<span>` containing `getErrorMessage(e)`, and KaTeX ParseError echoes
a slice of the user's TeX source. Self-XSS only (single-user editor), static on rr's site; consumer
risk only if other users' equations are rendered. **Fix:** HTML-escape the error before interpolation.
(Full XSS sweep otherwise clean — every other `dangerouslySetInnerHTML` is static, KaTeX `trust:false`,
Mermaid `securityLevel:strict`, or escaped.)

## 3. UI/UX & Accessibility

### P2 — Indonesian placeholder on an English site
`components/site/catalog/catalog-search.tsx:29`, `components/site/catalog/catalog-tabs.tsx:28`

Search default placeholder is `"Cari…"` while the rest of the UI is English. Mixed-language signal;
international users may miss that the field is searchable. **Fix:** `"Search slices…"` /
`"Search layouts…"`; keep Indonesian only inside locale-specific template content.

### P2 — Build compatibility warnings show the conflict but not the resolution
`components/build/command-output.tsx:28-43`

"X conflicts with Y" appears with no "how to resolve" path. Undercuts the builder's core promise of
emitting a working command. **Fix:** add an `action` field to the warning type — "Pick one" / "Manually
wire…" / "See docs" — and link conflicting slices to their detail pages.

### P2 — Project form has no inline validation
`components/build/project-form.tsx:26-50`

`app-name`, `brand`, `owner-email` accept anything; `My App` (spaces) silently produces a broken
downstream command. **Fix:** validate on blur (`app-name: ^[a-z0-9-]+$`, email format), show inline
error, disable "Copy command" while invalid.

### P2 — Copy buttons: no failure feedback, no `aria-pressed`
`components/site/copy-button.tsx:30-40`, `components/site/docs-sidebar/hero-strip.tsx:26,44`

Clipboard write can fail (permission/insecure context) with zero user signal; screen readers hear
"Copy" twice because state isn't announced. **Fix:** `toast.error` on failure; `aria-pressed={copied}`
+ dynamic `aria-label` ("Copied to clipboard").

### P2 — Sidebar collapsibles don't expose expand state to AT
`components/site/docs-sidebar/nav-parts.tsx:59-65`

Chevron rotates but there's no `aria-expanded` on the trigger. **Fix:** `aria-expanded={open}` on the
`CollapsibleTrigger`.

### P2 — Landing value-prop is diffuse; `npx rr add` is undiscoverable from the homepage
`components/site/hero.tsx:23-30`

A first-timer can't quickly answer "is this a template library / CLI / design system?" and the one-command
fast path (`npx rr add <slug>`) only surfaces after drilling into a slice. **Fix:** lead with a concrete
one-liner ("Copy-first slice library for Next.js — audited production components"), add a "Quick install"
code block, push the stack details below the fold.

### P2 — Terminology drift (slice / feature / kitab) in content & comments
Sitewide — e.g. `instrumentation.ts:11` ("kitab" comment), best-practices prompt, some admin/changelog copy.

Reads as a half-finished migration and risks teaching agents the wrong canonical noun. **Fix:** sweep
user-facing text + the best-practice prompt to "slice"; update stray "kitab"/"feature" comments.

### P3 — `/directory` exists but isn't linked in the sidebar
`components/site/docs-sidebar/build-sections.ts:42` — add a `{ kind:"leaf", title:"Directory", href:"/directory" }` leaf.

### P3 — Build panel cramped on tablet (768–1024px)
`components/build/build-shell.tsx:229-244` — 3 columns leave ~200px for previews. **Fix:** collapse the
Command panel behind a toggle below `max-w-6xl`.

### P3 — Changelog pager touch targets < 44px
`app/(docs)/changelog/page.tsx:68-92` — `size="sm"` buttons miss WCAG 2.5.5 on mobile. **Fix:** bump to
≥40px height on small screens.

### P3 — `⌘K` hint shown on mobile where it can't be used
`components/site/command-palette.tsx:54-56` — gate the `<kbd>` hint behind `hidden sm:inline-flex`.

## 4. Developer Experience & Tooling

### P2 — No contributor documentation at all
No `CONTRIBUTING.md` / `DEVELOPMENT.md` (verified absent). A new contributor can't tell `new:slice` from
`scaffold-slice`, doesn't know the `validate:all` tiers, or how to debug a failing hook. **Fix:** add a
short `CONTRIBUTING.md` (quick start, "adding a slice", validation tiers, hook-failure recovery).

### P2 — No npm workspaces → manual linking for CLI/MCP co-dev
Root `package.json` has no `workspaces` field (verified). Editing `packages/cli/lib` and testing it from
`packages/mcp` needs `npm link` gymnastics; CI can't verify the two packages interoperate without explicit
setup. **Fix:** add `"workspaces": ["packages/*"]` + document. (Flagged "deferred" in CLAUDE.md — the cost
is real DX friction, worth reconsidering.)

### P2 — CLI network/IO error paths are thin
`packages/cli/bin/cli.js` (pull/`tiged().clone()` path) — a DNS/branch/permission failure surfaces as a raw
`tiged` stack trace with no recovery hint and no partial-write check. **Fix:** wrap pull with
ENOTFOUND/ECONNREFUSED/ENOENT detection → actionable messages ("check connectivity", "verify repo is public"),
single retry on transient errors, and a post-pull existence check before printing "✓ Done".

### P2 — MCP tool descriptions are terse; errors are unstructured strings
`packages/mcp/src/tools-definitions.mjs`, `packages/mcp/src/handlers.mjs:53-75`

An LLM caller can't disambiguate `rr_compose_app` vs `rr_compose_add_commands` from the descriptions, and a
"Not found" error carries no code/severity so the agent can't retry intelligently. **Fix:** add "use when…"
to each tool description; return structured errors `{ error, message, code, suggestions }`.

### P2 — Skills/manifest sync is publish-time only → multi-week drift window
`lib/content/claude-skills.ts` → `sync-skills.mjs` is manual; `--check` only runs in CLI `prepublishOnly`.
Between releases the site can advertise a skill the CLI doesn't know. **Fix:** add `sync-skills.mjs --check`
to pre-commit (same pattern as `gen:agent-md:check`).

### P2 — Test coverage ~35% with the highest-risk flows untested
Core CLI journeys — `init`, `add` (idempotency / re-add), `update`, `compose` conflict-solver,
`promoteToRoot` file-moves, MCP resource-loader fallback — have no end-to-end coverage; existing tests are
mostly unit-level. Regressions surface post-publish. **Fix:** add an integration suite that scaffolds a temp
app and runs real CLI commands against fixture manifests; target 60%+ on `packages/cli/bin` + MCP handlers.

### P3 — Validation errors lack remediation hints
`scripts/validation/audit-slice.mjs` — e.g. "slug != folder" doesn't tell you to `mv` the folder. **Fix:**
append the concrete fix command to each error class.

### P3 — Pre-commit ordering runs the slow check (typecheck ~10s) without fail-fast on cheap checks
`.githooks/pre-commit` — reorder cheapest-first so contract/changelog drift fails in ~1s instead of after the
typecheck wait.

## 5. Architecture & Technical Debt

### P2 — Metadata SSOT is fragmented across up to 4 files
`slug` / `title` / `category` / `version` are independently declared in `lib/content/slices.ts`,
`slice.json`, `slice.manifest.json`, `config.ts`, and `slice.contract.ts`. `audit-slice.mjs` cross-checks
`slug`/`category` across the trio but **not against `slices.ts`** (2474 LOC, hand-curated). Drift grows with
time. **Fix:** declare `slices.ts`'s relationship to `slice.json` in CLAUDE.md (display-source vs truth-source),
and add a gate verifying every `slice.json` has a matching `slices.ts` entry.

### P2 — Version drift: `slice.json` ahead of `slice.contract.ts` on 12 slices
Verified: `notion-shell` 0.24.0 vs 0.5.0, `convex-auth` 0.4.0 vs 0.2.0, `loading-states` 0.2.0 vs 0.1.0, +9.
Ungated (audit passes), so impact is metadata hygiene, not runtime — but the 19-version `notion-shell` gap
signals real maintenance lag. **Fix:** decide which field is authoritative (`slice.json` is the CLI SSOT),
then either sync contracts or drop the contract `version` field; add a parity warn→error.

### P2 — `components/ui` ↔ `template-base/components/ui` divergence
Root 57 files / template 50 / 45 overlap; 12 root-only (combobox, date-field, field, input-otp, pagination,
spinner…), 5 template-only (Marquee, toast/toaster, shadcn-io…). Won't break consumers (they use root) but is
ongoing manual sync burden. The warn-only `report-ui-drift.mjs` exists; consolidation is deferred. **Fix:**
document which primitives must sync before a major release; consider promoting the drift report to a soft CI gate.

### P3 — `slice.contract.ts` import-path inconsistency (cosmetic)
20 contracts import `defineSliceContract` via `../../../packages/cli/lib/contract`, 49 via
`@/packages/cli/lib/contract`. `slice.contract.ts` is tsc-excluded and rr-internal (neither path ships to a
consumer), so this is **not** a Hard-Rule-5 runtime violation — purely style. **Fix (optional):** one sed sweep
to the alias form for consistency.

### P3 — Config export naming `*Feature` vs `*Config` (23 vs 46)
Cosmetic inconsistency; `audit-slice.mjs` checks the camelCase prefix but not the suffix. **Fix:** standardize
on `*Config` and lint it.

### P3 — Utility duplication `lib/utils.ts` ≡ `packages/shared/src/lib/utils.ts`
Intentional per the distribution split (internal vs npm-published), currently byte-identical, no gate guarding
against future drift. **Fix:** add a sync check or have one re-export the other where feasible.

**Largest files (refactor candidates as they grow):** `lib/content/slices.ts` (2474), `lib/content/layouts.ts`
(1464), `lib/content/changelog/part-01.ts` (1429).

## 6. What's genuinely good (don't regress these)

- **W1–W5 hardening is real and intact** — verified no regression across all five waves.
- **Auth above solo-dev average** — HMAC-signed sessions, scrypt + `timingSafeEqual`, PKCE OAuth with opaque
  generic errors, constant-time webhook signature checks.
- **Convex isolation is clean** — site schema composes only `rate_limit`; zero bare `.collect()`; queries use
  `.withIndex().take()`; 20 feature backends correctly kept off rr's own deployment.
- **Strong machine-enforced gates** — `audit:slices` + the validation chain + git hooks catch the structural
  classes early; `audit:slices` passes green today (1 unrelated className warning).
- **TS strict, no `any` abuse, no dead code** — the handful of `as unknown` casts are all justified library
  interop (Konva, react-dnd, WebKit).
